WEKNORA · KNOWLEDGE SELF-CHECK

知识自检页逻辑与实现说明

这份文档说明 WeKnora「知识自检」页面的业务逻辑、前后端实现、API、数据表、状态机、通知和定时任务。目标是让后续开发者能够从页面功能直接跳到对应代码和接口。

代码根目录：D:\OneDrive\文档\BF-knows 2\vendor\WeKnora。页面地址：http://localhost/platform/knowledge-selfcheck。

TOP

1. 页面目标

知识自检页用于检查项目知识库中的入口项目文档，是否满足其直接绑定的 SOP 文档中定义的实体交付物要求。

项目文档直接绑定 SOP每个入口项目文档绑定一个具体 SOP 文档。运行时读取 knowledge_selfcheck_document_mappings，不重新 fuzzy match。
只检查实体交付物只核对文档、表单、记录、截图、清单、PPT/演示稿等能在知识库归档的实体；动作和流程步骤不作为检查项。
只判断存在性当前版本只判断交付物是否能在项目文档标题或目录中找到，不判断内容质量和规范性。
保存、通知、定时每次自检保存 run 和 findings；缺失、不完整、待确认项通知负责人；支持每日定时自动执行。

5. 自检执行链路

核心入口：

1

2

3

4

5
读取绑定 SOP从 knowledge_selfcheck_document_mappings 读取 manual binding。
6

7

10

6. SOP 交付物提取逻辑

当前版本的原则是：优先规则抽取，规则只读取 SOP 中「产出物 / 交付物 / 输出物」小节，不读流程表，不读附件模板，不把动作当交付物。

缓存版本entity-artifacts-v9。版本变化后会避开旧缓存，重新抽取。knowledge_selfcheck.go:117-135

规则抽取定位产出物小节，解析 bullet、表格最后一列、顿号/逗号拆分。knowledge_selfcheck.go:1364-1474

7. 项目文档匹配规则

自检只判断交付物是否存在。证据来自项目知识库中同项目范围内文档的标题和目录标题。

方式说明状态倾向
文档标题命中文档标题包含交付物名称或别名。present
目录标题命中入口项目文档目录里存在交付物章节，例如「用户画像卡片」「用户旅程地图」「Story Board」。present 或 partial
组合交付物拆分例如「产品解决方案文档（包含：功能清单与优先级、架构图、解决方案文档）」会拆成组成项检查。按缺失组成项决定整体状态
语义别名例如「架构图」可匹配「信息架构图」。present
强实体PPT、会议纪要、申请表、计划表等明确实体不能只靠弱目录命中。missing 或 uncertain
  • buildSelfCheckScopeDocuments：确定项目证据范围。knowledge_selfcheck.go:701-724
  • extractSelfCheckHeadings：提取文档目录/标题。knowledge_selfcheck.go:740-756
  • matchSelfCheckArtifact：匹配主函数。knowledge_selfcheck.go:758-812
  • selfCheckArtifactAliases：别名表。knowledge_selfcheck.go:913-947
  • isSelfCheckStrongEvidenceArtifact：强实体判断。knowledge_selfcheck.go:948-952

当前系统不判断 PRD 是否写得好、原型是否高保真、架构图是否正确；只判断目录或标题层面是否存在。

8. 状态机

Run 状态

状态含义
running自检执行中。
completed执行完成并保存审计结果。注意：这不代表所有交付物都完成。
failed配置、读取、模型或数据库等不可恢复错误。

Finding 状态

状态页面展示含义
present已存在找到明确证据。
partial不完整组合交付物部分存在。
missing缺失未找到标题或目录证据。
uncertain待确认存在弱证据，但不足以确认。

9. 通知与定时任务

飞书通知

自检完成后，系统只通知需处理项：missing、partial、uncertain。已完成项不写入通知。

  • 通知负责人来自 knowledge_selfcheck_profiles.owner_open_id。
  • 发送机器人来自 knowledge_selfcheck_profiles.im_channel_id。
  • 发送函数：notifySelfCheckOwner，代码位置 knowledge_selfcheck.go:1072-1119。

每日定时

后端启动后调用 StartKnowledgeSelfCheckScheduler，每分钟检查一次是否到达配置时间。

字段/函数职责
daily_schedule每日自检时间，格式如 daily_0900。
last_run_at避免同一时间窗口重复执行。
runDueKnowledgeSelfChecks查找启用且到点的项目 profile 并执行自检。

代码位置：internal/handler/knowledge_selfcheck.go:1638-1715

常用 SQL

-- 文档级绑定
SELECT project_kb_id, project_document_id, sop_kb_id, sop_document_id,
       match_method, match_status, updated_at
FROM knowledge_selfcheck_document_mappings
ORDER BY updated_at DESC;

-- SOP 交付物缓存
SELECT sop_document_id, prompt_version, status,
       jsonb_array_length(requirements) AS requirement_count,
       error, updated_at
FROM knowledge_selfcheck_sop_deliverables
ORDER BY updated_at DESC;

-- 最近自检 run
SELECT id, project_kb_name, sop_kb_name, status, summary, started_at, completed_at
FROM knowledge_selfcheck_runs
ORDER BY started_at DESC
LIMIT 10;

-- 最近 findings
SELECT run_id, project_document_title, sop_document_title, requirement, state, evidence, suggestion
FROM knowledge_selfcheck_findings
ORDER BY created_at DESC
LIMIT 50;

常见问题

现象优先检查
页面没有入口文档绑定区域确认 frontend 镜像是否重建，页面 JS 是否为最新构建。
保存绑定成功但 DB 没记录查 knowledge_selfcheck_document_mappings 全表，确认 tenant 和 project_document_id。
SOP 交付物不准查 prompt_version 和 requirements，确认是否命中新缓存版本。
目录明明有却 missing检查目录抽取、别名表、强实体规则和证据文档范围。
没有飞书通知检查 owner_open_id、im_channel_id、enabled，并查看 app 日志中的 [KnowledgeSelfCheck] notify。
