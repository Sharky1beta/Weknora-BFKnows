# BF-Knows WeKnora 交付说明

## 1. 项目简介

本项目基于 WeKnora 构建，用于企业知识库的文档管理、知识检索和智能问答。

本次交付重点增加了两个管理能力：

- **质量监控页**：集中查看知识库运行质量、处理状态和相关监控指标，帮助管理员及时发现异常。
- **知识自检页**：对知识库内容和配置进行检查，定位缺失、异常或需要人工处理的知识问题。

除上述页面外，相关功能可能依赖前端路由、接口封装、后端 API、数据模型、权限配置、国际化文案和公共组件。因此交付时建议保留完整项目源码，不建议只复制页面文件。

## 3. 环境要求

推荐使用 Docker Compose 运行完整服务。开发或前端单独构建时，需要准备：

- Docker 和 Docker Compose
- Git
- Go（后端开发或源码构建）
- Node.js 与 npm/pnpm（前端开发或源码构建）
- PostgreSQL、Redis、对象存储和模型服务等依赖，具体以 `.env` 配置为准

## 4. 配置与启动

首次运行时复制环境变量模板：

```bash
cp .env.example .env
```

然后根据部署环境修改 `.env`，至少确认数据库、Redis、对象存储、模型服务、管理员账号和服务端口配置。

使用 Docker Compose 启动：

```bash
docker compose up -d
```

查看服务状态：

```bash
docker compose ps
```

查看日志：

```bash
docker compose logs -f
```

停止服务：

```bash
docker compose down
```

启动完成后，通常通过以下地址访问：

- Web 页面：`http://localhost`
- 后端 API：以 `.env` 中配置的端口为准

## 5. 新增功能使用说明

### 5.1 质量监控页

质量监控页用于观察知识问答运行过程中的质量表现和知识缺口情况。建议管理员重点关注：

- 知识问答命中率、未命中问题数量和响应耗时是否异常；
- 不同渠道、智能体的问答质量是否存在明显差异；
- 高频未命中问题是否需要补充知识库内容；
- 质量报告是否按配置周期生成，并在 AI 分析完成后发送到项目群；
- 自动发送失败、模型调用异常或报告生成失败时是否需要人工处理。

### 5.2 知识自检页

知识自检页用于检查项目知识库中的交付文档是否符合已绑定 SOP 的交付物要求。建议管理员重点关注：

- 项目知识库是否已启用自检，并配置负责人和通知机器人；
- 系统识别出的入口文档是否已绑定正确的 SOP 文档；
- SOP 中提取出的实体交付物是否准确，例如文档、表单、记录、截图、清单、PPT 等；
- 项目文档标题或目录中是否能匹配到对应交付物；
- 自检结果中的缺失、不完整或待确认项是否需要补充文档或人工确认；
- 定时自检是否按配置时间自动执行，并将需处理结果通知到飞书。

## 6. 前端开发与构建

进入前端目录后安装依赖：

```bash
cd frontend
npm install
```

启动前端开发服务：

```bash
npm run dev
```

执行类型检查和生产构建：

```bash
npm run type-check
npm run build
```

如果只修改了前端页面，仍需确认对应的路由、API、权限和国际化文件是否一并交付。

## 8. 已知注意事项

本项目包含较多外部依赖和可选服务。不同部署环境的模型、数据库、对象存储和权限配置可能不同，因此 README 中的默认地址和启动命令不能替代实际环境配置。正式交付前，应在一套干净环境中完成一次从配置、启动到两个新增页面验收的完整验证。
