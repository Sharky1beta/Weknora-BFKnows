# BF-Knows WeKnora 部署与交接说明

## 1. 项目简介

本交付包是基于 WeKnora 定制的企业知识库系统，用于知识库管理、知识检索和智能问答。

本版本包含两个新增管理能力：

- **质量监控页**：集中查看知识库运行质量、处理状态和相关监控指标，帮助管理员及时发现异常。
- **知识自检页**：对知识库内容和配置进行检查，定位缺失、异常或需要人工处理的知识问题。

除上述页面外，功能还依赖前端路由、接口封装、后端 API、数据模型、权限配置、国际化文案和公共组件。部署时请使用完整的 WeKnora 源码目录，不要只复制页面文件。

## 2. 目录说明

```text
WeKnora/
├── cmd/                 后端程序入口
├── internal/            后端业务逻辑、接口和数据访问
├── migrations/          数据库迁移
├── frontend/            Vue 前端工程
├── config/              配置文件和默认配置
├── deploy/              部署相关文件
├── docker/              Docker 构建和运行文件
├── docs/                项目文档
├── docker-compose.yml   Docker Compose 主配置
├── .env.example         环境变量模板
└── README_BF-KNOWS.md   本次交付说明
```

## 3. 环境要求

推荐使用 Docker Compose 运行完整服务。开发或前端单独构建时，需要准备：

- Docker 和 Docker Compose
- Git
- Go（后端开发或源码构建）
- Node.js 与 npm/pnpm（前端开发或源码构建）
- PostgreSQL、Redis、对象存储和模型服务等依赖，具体以 `.env` 配置为准

## 4. 配置与启动

部署前，请先复制环境变量模板：

```bash
cp .env.example .env
```

然后根据部署环境填写 `.env`。至少需要配置数据库、Redis、对象存储、模型服务、管理员账号和服务端口。真实密钥不会放在本交付包中，请向交付方单独获取。

构建并启动服务：

```bash
docker compose up -d
```

如果使用源码构建，请先执行：

```bash
docker compose build app frontend
```

查看服务状态：

```bash
docker compose ps
```

查看日志：

```bash
docker compose logs -f
```

停止服务：

```bash
docker compose down
```

启动完成后，通常通过以下地址访问：

- Web 页面：`http://localhost`
- 后端 API：以 `.env` 中配置的端口为准

## 5. 新增功能使用说明

### 5.1 质量监控页

质量监控页用于观察知识问答运行过程中的质量表现和知识缺口情况。建议管理员重点关注：

- 知识问答命中率、未命中问题数量和响应耗时是否异常；
- 不同渠道、智能体的问答质量是否存在明显差异；
- 高频未命中问题是否需要补充知识库内容；
- 质量报告是否按配置周期生成，并在 AI 分析完成后发送到项目群；
- 自动发送失败、模型调用异常或报告生成失败时是否需要人工处理。

### 5.2 知识自检页

知识自检页用于检查项目知识库中的交付文档是否符合已绑定 SOP 的交付物要求。建议管理员重点关注：

- 项目知识库是否已启用自检，并配置负责人和通知机器人；
- 系统识别出的入口文档是否已绑定正确的 SOP 文档；
- SOP 中提取出的实体交付物是否准确，例如文档、表单、记录、截图、清单、PPT 等；
- 项目文档标题或目录中是否能匹配到对应交付物；
- 自检结果中的缺失、不完整或待确认项是否需要补充文档或人工确认；
- 定时自检是否按配置时间自动执行，并将需处理结果通知到飞书。

## 6. 前端开发与构建

进入前端目录后安装依赖：

```bash
cd frontend
npm install
```

启动前端开发服务：

```bash
npm run dev
```

执行类型检查和生产构建：

```bash
npm run type-check
npm run build
```

如果只修改了前端页面，仍需确认对应的路由、API、权限和国际化文件是否一并交付。

## 7. 接收与恢复说明

仅有源码目录无法恢复完整的生产运行状态。完整部署还需要数据库备份、知识库文件数据和运行所需的敏感配置。

### 7.1 部署包内容

请确认收到以下内容：

- `vendor/WeKnora/`：当前修改后的 WeKnora 源码目录；
- `.env.example` 等必要配置模板，不包含真实 API Key、App Secret 或 Token；
- PostgreSQL 数据库备份，建议使用 `pg_dump` 导出；
- 知识库文档、上传文件和解析后文件所在的本地 volume 或文件数据目录；
- 本 README 和部署启动说明；
- 由交付方单独提供的敏感配置。

PostgreSQL 备份用于恢复知识库、自检配置、模型配置和报告历史。知识库文档、上传文件和解析后文件如果存储在本地 volume 中，也必须一起恢复，否则仅恢复数据库可能缺少实际文档数据。

模型 API Key、飞书 `app_id`、`app_secret`、机器人配置及其他密钥不会放入压缩包或 Git，请通过安全渠道单独获取并填写到 `.env`。

### 7.2 数据恢复

收到 PostgreSQL 备份后，请先创建目标数据库，再使用 `pg_restore` 或 `psql` 导入。收到文件数据目录后，请将其恢复到部署配置指定的 volume 或存储目录，并确认容器用户具有读写权限。

完成配置和数据恢复后，执行：

```bash
docker compose build app frontend
docker compose up -d
```

### 7.3 仅开发源码交接

如果本次交接仅用于继续开发，交付内容可以只有：

- `vendor/WeKnora/` 源码；
- `.env.example`；
- 数据库结构迁移文件；
- 本 README 和开发启动说明。

此类交接包不包含生产数据库、Redis 数据或全部用户文件，接收方需要自行准备本地开发环境和测试数据。

- [ ] 数据库迁移和初始化步骤已经验证；
- [ ] `.env` 中没有真实密钥；
- [ ] 已记录本次版本涉及的文件和已知问题。

## 9. 已知注意事项

本项目包含较多外部依赖和可选服务。不同部署环境的模型、数据库、对象存储和权限配置可能不同，因此 README 中的默认地址和启动命令不能替代实际环境配置。正式交付前，应在一套干净环境中完成一次从配置、启动到两个新增页面验收的完整验证。
