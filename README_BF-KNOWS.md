# BF-Knows WeKnora 部署与交接说明

本交付包是基于 WeKnora 定制的企业知识库系统，包含质量监控页和知识自检页。

## 配置与启动

部署前复制配置模板：

```bash
cp .env.example .env
```

请根据部署环境填写数据库、Redis、对象存储、模型服务、管理员账号和端口配置。模型 API Key、飞书 `app_id`、`app_secret`、机器人配置等敏感信息不会放入本仓库，请通过安全渠道单独获取。

使用源码构建并启动：

```bash
docker compose build app frontend
docker compose up -d
```

查看状态和日志：

```bash
docker compose ps
docker compose logs -f
```

## 新增功能

### 质量监控页

质量监控页用于观察知识问答运行过程中的质量表现和知识缺口情况。建议管理员重点关注：

- 知识问答命中率、未命中问题数量和响应耗时是否异常；
- 不同渠道、智能体的问答质量是否存在明显差异；
- 高频未命中问题是否需要补充知识库内容；
- 质量报告是否按配置周期生成，并在 AI 分析完成后发送到项目群；
- 自动发送失败、模型调用异常或报告生成失败时是否需要人工处理。

### 知识自检页

知识自检页用于检查项目知识库中的交付文档是否符合已绑定 SOP 的交付物要求。建议管理员重点关注：

- 项目知识库是否已启用自检，并配置负责人和通知机器人；
- 系统识别出的入口文档是否已绑定正确的 SOP 文档；
- SOP 中提取出的实体交付物是否准确，例如文档、表单、记录、截图、清单、PPT 等；
- 项目文档标题或目录中是否能匹配到对应交付物；
- 自检结果中的缺失、不完整或待确认项是否需要补充文档或人工确认；
- 定时自检是否按配置时间自动执行，并将需处理结果通知到飞书。

## 数据与敏感配置

仅有源码无法恢复完整生产状态。完整部署还需要：

- PostgreSQL 数据库备份，用于恢复知识库、自检配置、模型配置和报告历史；
- 知识库文档、上传文件和解析后文件所在的文件目录或 volume；
- 通过安全渠道单独交接的模型 API Key、飞书应用配置和其他密钥。

恢复数据库和文件数据后，再执行上述 Docker 构建与启动命令。

## 开发说明

前端目录为 `frontend/`。开发时可执行：

```bash
cd frontend
npm install
npm run dev
```

生产构建和类型检查：

```bash
npm run type-check
npm run build
```
